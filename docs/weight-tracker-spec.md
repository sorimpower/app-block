# 체중·식사 기록 기능명세서

문서 상태: 구현 진행 1.2
기능명: **Body Log (체중·식사 기록)**
대상 앱: 소림파워 Android 앱

현재 구현: Room 기반 체중·목표·식사·사진 CRUD, 날짜 지정 입력, 달력 선택 날짜별 식사 목록, 일·주·월·연 그래프, 월 달력, 7일 평균
후속 구현: 상세 단위 설정, Health Connect

## 1. 기능 개요

사용자가 매일 체중과 먹은 음식을 기록하고, 실제 변화량과 장기 추세를 일·주·월·연 단위로 확인하는 기능이다. 단순히 전날 수치만 비교하지 않고 이동평균과 기간별 변화량을 함께 보여줘 수분이나 식사로 인한 단기 변동에 과도하게 반응하지 않도록 한다. 식사 기록은 복잡한 영양 계산보다 그날 무엇을 먹었는지 빠르게 남기고 되돌아보는 데 집중한다.

핵심 가치는 다음과 같다.

- 오늘 체중을 몇 초 안에 기록한다.
- 아침·점심·저녁·간식별로 오늘 또는 과거에 먹은 음식을 간단히 기록한다.
- 시작 체중, 현재 체중, 목표 체중의 차이를 즉시 확인한다.
- 달력과 그래프로 체중 변화와 날짜별 식사 기록을 함께 파악한다.
- 모든 데이터는 기본적으로 기기에만 저장한다.

## 2. 목표와 제외 범위

### 목표

- 매일 부담 없이 체중을 입력·수정·삭제할 수 있어야 한다.
- 음식 이름과 식사 종류를 중심으로 식사 기록을 빠르게 입력·수정·삭제할 수 있어야 한다.
- 하루에 여러 번 측정한 기록도 손실 없이 보존해야 한다.
- 일간, 주간, 월간, 연간 그래프가 같은 집계 규칙을 사용해야 한다.
- 목표까지 남은 변화량과 최근 추세를 이해하기 쉽게 제공해야 한다.
- 기존 홈에서 App Blocker와 동등한 독립 기능으로 진입할 수 있어야 한다.

### 1차 버전에서 제외

- 음식 데이터베이스 검색, 바코드 인식, 영양소 및 칼로리 정밀 계산
- 운동 자동 측정
- 의료 진단이나 감량 속도 처방
- 계정, 서버 동기화, 사용자 간 경쟁
- 스마트 체중계 제조사별 직접 연동

## 3. 용어와 계산 기준

- **측정 기록:** 사용자가 특정 날짜와 시각에 입력한 원본 체중값이다.
- **일일 대표 체중:** 해당 날짜의 마지막 측정 기록이다. 하루에 한 번만 입력했다면 그 값이 대표값이다.
- **주간 변화량:** 이번 주의 마지막 대표 체중에서 첫 대표 체중을 뺀 값이다.
- **월간 변화량:** 해당 월의 마지막 대표 체중에서 첫 대표 체중을 뺀 값이다.
- **7일 추세:** 최근 7개 날짜의 일일 대표 체중 평균이다. 기록이 없는 날짜는 0으로 채우지 않고 계산에서 제외한다.
- **시작 대비 변화:** 현재 대표 체중에서 목표를 시작할 때의 체중을 뺀 값이다.
- **목표까지 남은 변화:** 현재 대표 체중과 목표 체중의 절댓값 차이다. 증량 목표도 지원한다.
- 모든 내부 체중값은 `kg`으로 저장하고 표시 단계에서 `kg` 또는 `lb`로 변환한다.
- 날짜 구분은 기록 당시의 현지 날짜와 시간대 오프셋을 보존하여 계산한다.

## 4. 사용자 흐름

### 최초 설정

1. 홈에서 **Body Log** 카드를 선택한다.
2. 단위를 `kg` 또는 `lb`로 선택한다. 기본값은 `kg`이다.
3. 현재 체중과 목표 체중을 입력한다.
4. 선택 사항으로 목표일과 키를 설정한다.
5. 최초 체중을 시작 기록으로 저장하고 대시보드로 이동한다.

### 매일 기록

1. Body Log 대시보드에서 **체중 기록**을 선택한다.
2. 직전 기록값이 입력창의 기준값으로 표시된다.
3. 숫자 키패드 또는 `- / +` 버튼으로 체중을 조절한다.
4. 측정 날짜, 메모, 측정 조건을 선택적으로 입력한다.
5. 저장 직후 오늘 변화량과 7일 추세를 갱신한다.

### 식사 기록

1. Body Log 대시보드의 **식사 기록**에서 `+ 기록`을 선택한다.
2. `아침 / 점심 / 저녁 / 간식` 중 식사 종류를 선택한다.
3. 먹은 음식 이름을 한 줄씩 입력한다. 예: `현미밥`, `닭가슴살 샐러드`, `아메리카노`.
4. 식사 날짜를 선택하고, 선택 사항으로 양, 사진, 메모와 컨디션 태그를 추가한다.
5. 저장하면 최신 날짜부터 정렬된 날짜별 식사 목록에 즉시 표시한다.

### 과거 기록 확인 및 수정

1. 달력에서 날짜를 선택한다.
2. 해당 날짜의 모든 측정 기록을 시간순으로 표시한다.
3. 기록을 선택해 체중·시각·메모를 수정하거나 삭제한다.
4. 변경 후 모든 통계와 그래프를 즉시 다시 계산한다.

## 5. 화면 명세

### 5.1 기능 홈 카드

- 카드 제목: `Body Log`
- 보조 문구: 오늘 기록 전에는 `오늘 체중을 기록해 주세요`, 기록 후에는 `현재 72.4 kg · 목표까지 4.4 kg`
- 최근 7일 추세를 나타내는 작은 스파크라인
- 카드 선택 시 Body Log 대시보드로 이동

### 5.2 Body Log 대시보드

상단 요약 영역:

- 현재 체중
- 시작 대비 변화량
- 목표까지 남은 변화량
- 최근 7일 평균
- 마지막 기록 시각

오늘 식사 영역:

- `아침 / 점심 / 저녁 / 간식` 순서의 타임라인
- 식사별 대표 사진, 음식 이름과 기록 시각
- 오늘 입력한 식사 수
- 비어 있는 식사에는 `무엇을 먹었나요?` 빠른 기록 버튼
- 기록을 선택하면 수정, 길게 누르거나 메뉴에서 삭제

주요 동작:

- 강조 버튼 `오늘 체중 기록`
- 기간 탭 `일 / 주 / 월 / 연`
- 그래프 좌우 이동 및 `오늘` 복귀
- 그래프의 점을 선택하면 날짜, 체중, 전 기록 대비 변화량 표시

상태별 표시:

- 기록 없음: 최초 기록 유도 화면
- 오늘 기록 없음: 부드러운 기록 안내
- 오늘 기록 완료: 재입력을 허용하되 `오늘 기록이 이미 있어요` 안내
- 목표 달성: 축하 카드와 새 목표 설정 동작

### 5.3 체중 입력 시트

필수 항목:

- 체중: 소수점 한 자리, `20.0~400.0 kg` 범위
- 측정 날짜와 시각: 기본값은 현재 시각, 미래 시각은 저장 불가

선택 항목:

- 메모: 최대 200자
- 측정 조건: `기상 직후`, `식전`, `식후`, `운동 전`, `운동 후`, `기타`
- 체지방률: `1.0~75.0%`

입력 UX:

- 직전 체중을 기본값으로 제공
- `-0.1`, `+0.1`, `-1`, `+1` 빠른 조절
- 동일 시각 기록이 있으면 덮어쓰지 않고 수정 여부 확인
- 저장 성공 후 짧은 햅틱과 변화 요약 표시

### 5.4 기간별 그래프

#### 일간

- 선택한 날짜의 모든 측정값을 시간순 선 그래프로 표시
- 최저, 최고, 마지막 측정값 표시
- 측정이 하나면 점과 값만 표시

#### 주간

- 월요일부터 일요일까지 일일 대표 체중 표시
- 기록 없는 날은 선을 임의로 연결하지 않고 공백으로 표시
- 주간 시작값, 종료값, 변화량, 평균 표시

#### 월간

- 날짜별 대표 체중 선 그래프
- 7일 이동평균을 보조선으로 표시
- 월간 최소, 최대, 평균, 변화량 표시
- 그래프 아래 월 달력을 제공하고 기록일에는 체중과 전 기록 대비 증감 색상을 표시

#### 연간

- 52주 단위 주간 평균 그래프
- 월별 평균점을 강조 표시
- 연간 시작값, 종료값, 최소, 최대, 평균, 총 변화량 표시
- 월을 선택하면 해당 월 화면으로 이동

공통 그래프 규칙:

- 감량을 무조건 초록색으로 표현하지 않는다. 목표 방향과 일치하면 목표색, 반대면 경고색을 사용한다.
- Y축을 지나치게 확대해 작은 변화가 과장되지 않도록 최소 표시 범위를 둔다.
- 원본 측정점, 일일 대표값, 평균선의 범례를 제공한다.
- 스크린 리더용 날짜·체중·변화량 설명을 각 데이터 점에 제공한다.
- 그래프의 날짜를 선택하면 해당 날짜에 기록한 식사 요약을 함께 표시한다.

### 5.5 기록 달력과 기록 목록

- 월 달력의 각 날짜에 대표 체중과 식사 기록 여부를 서로 다른 아이콘으로 표시
- 날짜 선택 시 그날의 모든 체중 기록, 식사 타임라인과 메모 표시
- 목록 필터: 전체, 체중, 식사, 메모 있음, 체지방 있음
- 정렬: 최신순과 오래된순
- 스와이프 삭제 시 확인 또는 실행 취소 제공

### 5.6 식사 입력 시트

필수 항목:

- 식사 종류: `아침`, `점심`, `저녁`, `간식`
- 음식 항목: 하나 이상의 음식 이름, 항목당 최대 60자
- 섭취 날짜와 시각: 기본값은 현재 시각, 미래 시각은 저장 불가

선택 항목:

- 양: 자유 입력, 최대 30자. 예: `1공기`, `반 개`, `350ml`
- 사진: 한 식사당 최대 3장, 갤러리 선택 또는 카메라 촬영
- 메모: 최대 200자
- 컨디션 태그: `배고픔`, `적당함`, `과식`, `외식`, `야식`, `직접 입력`

입력 UX:

- 음식 항목을 여러 줄로 추가·정렬·삭제
- 사진을 선택하거나 바로 촬영하고 저장 전에 미리보기·삭제·순서 변경
- 최근 입력한 음식과 자주 먹는 음식 제안
- 이전 식사를 복사해 날짜와 시각만 바꾸는 기능
- 칼로리는 필수 입력으로 요구하지 않음
- 사진 권한을 거절해도 텍스트 기록은 정상 사용 가능

### 5.7 목표 설정

- 시작 체중은 목표 생성 시점의 최신 체중으로 자동 입력하되 수정 가능
- 목표 체중 필수, 목표일 선택
- 감량과 증량 목표를 자동 판별
- 진행률은 `(시작 체중 - 현재 체중) / (시작 체중 - 목표 체중)` 기준으로 계산하고 `0~100%`로 제한
- 목표일 예상치는 참고 정보로만 표시하며 건강 결과를 보장하는 문구는 사용하지 않음
- 과거 목표는 완료·중단 상태로 보관

### 5.8 Body Log 설정

- 표시 단위: `kg / lb`
- 소수점 자릿수: 기본 한 자리
- 주 시작 요일: 월요일 또는 일요일
- 자주 먹는 음식 목록 관리
- 키 입력 시 햅틱 사용 여부
- 전체 체중 데이터 삭제
- 향후 Health Connect 연결 상태 및 권한 관리

## 6. 데이터 명세

반복되는 시계열 데이터이므로 기존 설정용 DataStore에 넣지 않고 Room을 사용한다.

### WeightEntry

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | UUID String | 기록 고유 ID |
| `weightKg` | Double | kg 기준 원본값 |
| `measuredAt` | Instant/Long | 측정 시각 |
| `zoneOffsetMinutes` | Int | 기록 당시 시간대 오프셋 |
| `bodyFatPercent` | Double? | 선택 체지방률 |
| `condition` | Enum? | 측정 조건 |
| `note` | String? | 최대 200자 메모 |
| `source` | Enum | MANUAL 또는 HEALTH_CONNECT |
| `externalId` | String? | 외부 동기화 중복 방지 ID |
| `createdAt` | Instant/Long | 생성 시각 |
| `updatedAt` | Instant/Long | 수정 시각 |

### WeightGoal

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | UUID String | 목표 고유 ID |
| `startWeightKg` | Double | 시작 체중 |
| `targetWeightKg` | Double | 목표 체중 |
| `startedOn` | LocalDate | 시작일 |
| `targetDate` | LocalDate? | 선택 목표일 |
| `status` | Enum | ACTIVE, COMPLETED, CANCELLED |

### MealEntry

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | UUID String | 식사 기록 고유 ID |
| `mealType` | Enum | BREAKFAST, LUNCH, DINNER, SNACK |
| `eatenAt` | Instant/Long | 섭취 시각 |
| `zoneOffsetMinutes` | Int | 기록 당시 시간대 오프셋 |
| `note` | String? | 최대 200자 메모 |
| `tags` | Set<String> | 컨디션 및 사용자 태그 |
| `createdAt` | Instant/Long | 생성 시각 |
| `updatedAt` | Instant/Long | 수정 시각 |

### MealItem

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | UUID String | 음식 항목 고유 ID |
| `mealEntryId` | UUID String | 소속 식사 기록 ID |
| `name` | String | 음식 이름, 최대 60자 |
| `amount` | String? | 사용자가 입력한 양 |
| `sortOrder` | Int | 식사 안에서 표시 순서 |

### MealPhoto

| 필드 | 형식 | 설명 |
|---|---|---|
| `id` | UUID String | 사진 고유 ID |
| `mealEntryId` | UUID String | 소속 식사 기록 ID |
| `localPath` | String | 앱 내부에 복사된 이미지 경로 |
| `thumbnailPath` | String | 목록·달력용 축소 이미지 경로 |
| `width` | Int | 저장 이미지 너비 |
| `height` | Int | 저장 이미지 높이 |
| `sortOrder` | Int | 대표 사진 및 표시 순서 |
| `createdAt` | Instant/Long | 추가 시각 |

사진 저장 규칙:

- 시스템 Photo Picker의 다중 이미지 선택을 사용해 전체 사진 라이브러리 권한을 요구하지 않는다.
- 기본 카메라 앱 촬영은 `TakePicture` 계약과 앱 전용 `content://` URI를 사용한다.
- 선택한 원본은 장기 URI 권한에 의존하지 않고 앱 내부 저장소로 복사한다.
- 화면 표시 방향을 보정하고 긴 변 기준 최대 2,048px로 축소한 JPEG 또는 WebP 사본을 저장한다.
- 원본 EXIF의 위치정보는 앱 내부 사본에서 제거한다.
- 목록용 썸네일을 별도로 생성해 대용량 원본을 반복 디코딩하지 않는다.
- 식사 기록이나 개별 사진 삭제 시 이미지와 썸네일 파일도 함께 삭제한다.
- 앱 삭제 시 사진도 함께 삭제되며, 앱 내부 기록 화면 밖으로 자동 전송하지 않는다.

### 표시 설정(후속 구현)

단위, 주 시작 요일, 키 등 단순 설정은 DataStore에 저장한다.

### 필수 쿼리

- 날짜 범위의 모든 기록 조회
- 날짜별 마지막 기록 조회
- 날짜별 평균·최저·최고 조회
- 최근 기록 1건 조회
- 특정 날짜의 모든 기록 조회
- 외부 ID로 기록 조회 및 갱신
- 날짜 범위와 식사 종류별 식사 기록 조회
- 최근 음식 및 자주 먹는 음식 조회
- 식사 기록 삭제 시 연결된 음식 항목과 사진 레코드를 트랜잭션으로 함께 삭제

## 7. 추가 기능 제안

### 1차 출시 권장

- 목표 체중과 진행률
- 7일 이동평균
- 메모 및 측정 조건 태그
- 날짜별 식사 목록과 식사 종류별 빠른 기록
- 갤러리 선택·카메라 촬영을 이용한 식사 사진 기록
- 최근 음식·자주 먹는 음식 자동 완성
- 목표 달성 또는 기록 습관에 대한 비경쟁형 배지

### 2차 출시 권장

- 체지방률, BMI, 허리둘레 등 선택 신체 지표
- 신체 변화 사진과 식사 사진 비교 보기
- 선택형 칼로리·단백질·탄수화물·지방 기록
- 음식 바코드 및 영양정보 데이터베이스 연동
- 여러 목표 이력과 목표 구간 비교
- 달력에서 운동일·과식일·수면 부족일 등의 사용자 태그 겹쳐 보기
- 앱 위젯 또는 빠른 설정을 통한 오늘 체중 입력

### Health Connect 연동

- 사용자가 명시적으로 허용했을 때 체중 읽기와 쓰기 제공
- 앱의 Room 데이터베이스를 기준 데이터로 유지하고 Health Connect와 증분 동기화
- `clientRecordId`와 버전으로 중복 및 수정 충돌 방지
- Android 8(API 26)~8.1(API 27)에서는 로컬 기록만 제공하고, 지원 기기에서만 연결 메뉴 표시
- 1차 버전에는 넣지 않고 로컬 기록 안정화 후 추가 권장

### 권장하지 않는 기능

- 매일의 자연스러운 체중 증가를 실패로 표현하는 경고
- 근거 없이 목표일까지의 체중을 단정하는 예측
- 기본값으로 공개되는 체중 공유 및 순위 기능
- 삭제 확인 없이 대량 기록을 지우는 동작
- 사용 동의 없이 건강 데이터를 외부 서비스로 전송하는 동작

## 8. 알림 정책

Body Log의 매일 기록 알림은 제공하지 않는다. 기록은 사용자가 원하는 날짜를 직접 선택해 수동으로 남긴다.

## 9. 오류 및 경계 조건

- 날짜가 바뀌거나 시간대가 변경돼도 기록 당시 현지 날짜 유지
- 윤년, 월말, 주차가 연도를 넘는 경우 지원
- 하루 여러 기록을 저장해도 일일 대표값은 항상 가장 늦은 측정 시각 기준
- 기록 삭제로 대표값이 사라지면 같은 날짜의 직전 기록을 새 대표값으로 사용
- 단위 변경 시 저장값을 재작성하지 않고 표시값만 변환
- 빈 기간은 0 kg으로 그리지 않고 `기록 없음`으로 표시
- Health Connect와 동일 기록이 들어오면 외부 ID와 수정 버전으로 중복 방지
- 식사 기록에서 음식 항목을 모두 삭제하려 하면 식사 전체를 삭제할지 확인
- 사진 파일이 삭제되거나 접근할 수 없으면 텍스트 기록은 유지하고 사진 자리만 오류 표시
- 사진 복사·압축 중 앱이 종료되면 완료되지 않은 임시 파일을 다음 실행에서 정리
- 저장 공간이 부족하면 텍스트 식사는 저장할 수 있게 하고 사진 저장 실패를 별도로 안내

## 10. 개인정보 및 안전

- 체중 기록은 민감한 건강 정보로 취급하고 기본 저장 위치를 기기 내부로 제한
- 삭제 시 대상 기간과 복구 불가 여부를 명확하게 확인
- 로그와 크래시 보고서에 체중, 메모, 목표값을 기록하지 않음
- 식사 내용과 사진도 로그, 알림 미리보기, 외부 저장소에 기본 노출하지 않음
- BMI나 변화 추세는 참고 정보이며 의료 진단이 아님을 표시

## 11. 접근성

- 색상만으로 증가·감소를 구분하지 않고 화살표와 텍스트 병기
- 모든 그래프에 같은 내용을 제공하는 표 또는 요약 문장 제공
- 최소 터치 영역 48dp 유지
- 동적 글꼴 크기에서 주요 수치가 잘리지 않도록 줄바꿈 지원
- 체중 입력 시 단위와 소수점 형식을 스크린 리더가 읽을 수 있게 설명
- 식사 타임라인에서 식사 종류, 음식 이름, 시각을 하나의 읽기 순서로 제공

## 12. 완료 조건

- 사용자가 오늘 및 과거 날짜에 체중을 생성·수정·삭제할 수 있다.
- 사용자가 오늘 및 과거 날짜에 식사와 여러 음식 항목을 생성·수정·삭제할 수 있다.
- 사용자가 식사마다 사진을 최대 3장까지 선택·촬영·재정렬·삭제할 수 있다.
- 하루 여러 기록과 일일 대표값이 정의한 규칙대로 동작한다.
- 일·주·월·연 그래프와 월 달력이 같은 원본 데이터로 계산된다.
- 시작 대비, 목표까지, 기간 변화량, 7일 평균이 정확히 계산된다.
- 앱 재시작과 기기 재부팅 후에도 데이터가 유지된다.
- 빈 데이터, 단일 기록, 여러 기록, 단위 변경, 시간대 변경을 처리한다.
- 전체 데이터 삭제가 동작한다.
- 월 달력에서 체중 기록일과 식사 기록일을 구분하고 날짜별 상세를 열 수 있다.
- TalkBack과 큰 글꼴에서 핵심 입력·조회 흐름을 완료할 수 있다.

## 13. 구현 순서 제안

1. Room 데이터 모델, DAO, Repository와 계산 테스트
2. 최초 설정과 체중 입력·수정·삭제
3. 식사·음식 항목·사진 입력과 날짜별 목록
4. 대시보드와 일·주·월·연 집계
5. 그래프와 월 달력 및 날짜별 식사 상세
6. 목표와 기록 편의 기능
7. 접근성 보완
8. 별도 단계로 Health Connect 연동
