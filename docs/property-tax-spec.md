# 부동산 세금 포트폴리오 기능 명세

## 목적

사용자가 복잡한 세무 입력 없이 현재 상황과 계획을 자연어로 작성하면 AI가 자산·명의·날짜를 구조화하고, 최신 공식 법령을 검색해 매도 순서별 비과세·일반과세 가능성을 비교한다. 정확한 세액이 필요할 때만 선택적으로 자산을 등록해 deterministic Tax Engine 계산과 세법 버전별 Revision을 사용한다.

## 사용자 화면

- `AI 계획`: 현재 상황과 매도·입주 계획을 자유롭게 입력하고 공식 법령 기반 타임라인, 추천 매도 순서, 대안별 세금 처리 가능성, 법정 기한, 최소 추가질문과 다음 행동을 확인
- `자산`: 상세 세액 계산이 필요할 때만 여러 부동산을 간편 등록하고 취득 단계 예상세금과 연간 보유세 확인
- 부동산은 이름·유형·취득일·취득가 네 가지만으로 간편 등록할 수 있다. 주소·계약일, 재개발 상세, 소유·거주, 보유세, 양도세 필요경비와 전문 세금 설정은 접이식 선택 영역으로 분리하며 모르는 값은 비워둔 채 나중에 수정할 수 있다.
- 등록된 자산 카드에는 긴 Missing Input 원문 대신 `기본 등록 완료`와 다음에 보완하면 좋은 한 가지 정보를 표시한다. 재개발 자산은 주요 자료 입력 수를 표시한다.
- `상세 계산`: 부동산·예상 매도일·매도가·추가 필요경비를 입력한 양도세 계산 및 저장
- `세법`: 활성 Rule Version, 계산 범위와 공식 근거 표시
- 최상단 `정보` 버튼: Rule Engine 계산 → 공식 법령 실시간 확인 → 현재 기준 및 직전 분석 비교 → 근거·안전 상태 표시 과정을 요약 안내
- 내부 탭은 좌우 스와이프하며 끝 탭에서 한 번 더 넘기면 인접 앱 기능으로 이동한다.
- 홈과 하단 탭의 `세금` 진입점을 제공한다. 기존 설치에는 마이그레이션 시 한 번 자동 추가되며 이후에는 사용자의 탭 표시·순서 설정을 존중한다.

## 데이터

전용 Room DB `property_tax.db`에 다음 테이블을 둔다.

- `property_tax_properties`: 주택·분양권·조합원입주권, 취득정보, 본인/배우자 지분, 생년월일, 공시가격, 조정대상지역, 입주예정일, 필요경비, 실거주기간, 세목별 주택 수 처리, 도시지역분·지역자원시설세, 공동명의 특례 신청 상태, 재개발 전 기존 주택의 관리처분·멸실·준공 이력과 추가분담금·청산금
- `property_tax_rule_versions`: 시행일 기준 활성 세법 버전 및 공식 출처
- `property_tax_simulations`: 저장된 양도 시뮬레이션과 최신 계산 결과
- `property_tax_simulation_revisions`: 재계산 전후 결과를 덮어쓰지 않는 이력
- `property_tax_scenarios`, `property_tax_scenario_transactions`: 복수 거래 시나리오와 순서가 보존되는 취득·매도 단계
- `property_tax_ai_cache`: 이름은 기존 스키마와의 호환을 위해 유지한다. 캐시 응답 용도가 아니라 시뮬레이션별 공식 법령 분석 이력으로 사용하며 각 실행 결과·공식 출처·확인 시각·비교 결과를 별도 Row로 누적한다.
- `property_tax_ai_plans`: 사용자가 입력한 자연어 상황·계획과 AI의 구조화된 타임라인·시나리오·추가질문·공식 출처를 실행별로 저장한다. 첫 화면에는 최신 성공 분석을 복원한다.

주소·금액은 Logcat, Analytics, Crashlytics에 출력하지 않는다.

## Tax Rule Engine

활성 버전은 `KR_PROPERTY_TAX_2026_08_REDEVELOPMENT`이며 거래일 적용 가능 기간은 2026-07-01~2026-12-31, 보유세 적용연도는 2026년이다. 적용 기간 밖의 취득일·양도일·보유세 연도에는 2026년 규칙을 임의 적용하지 않고 `calculationAvailable=false`로 반환한다. 모든 결과는 적용 Rule, 중간 계산 Trace, Missing Input, 신뢰도와 Rule Version을 반환하며 법정 예외를 모두 확인하지 않은 계산은 `HIGH`로 표시하지 않는다.

### 취득세

- 개인의 유상 주택 취득 표준세율 1~3%를 계산한다. 지분 취득은 전체 주택가액으로 세율 구간을 정한 뒤 본인·배우자 취득 지분가액에 세율을 적용한다.
- 6억~9억원 구간은 연속 세율식을 사용한다.
- 지방교육세를 별도 표시한다.
- 농어촌특별세는 임의 추정하지 않는다. 확인된 세액을 선택 입력해 합계에 포함하며 미입력 시 제외 사실을 Missing Input으로 표시한다.
- 포트폴리오의 주택·2020년 8월 12일 이후 분양권·조합원입주권·오피스텔을 유형별로 판정하고 사용자가 `자동/포함/제외`를 교정할 수 있다. 상가·토지는 단순 개수에 포함하지 않는다.
- 취득 후 2주택이고 종전주택 처분일이 신규 취득일부터 3년 이내이면 일시적 2주택 표준세율을 적용한다.
- 분양권·조합원입주권 자체에는 주택 취득세를 계산하지 않고 완공 취득 시점의 세대 주택 수와 지역으로 다시 계산하도록 표시한다. 상가·토지 등 미지원 유형은 주택세율 계산 자체를 중단한다.
- 재개발 전 기존 주택을 취득한 원조합원 자산은 기존 매수가를 신축주택의 일반 유상 취득가로 보아 취득세를 재계산하지 않는다. 종전 토지·건축물, 증가 면적, 청산금 및 감면 자료가 없으므로 실제 취득세 고지액을 입력받고 세목별 적정성은 확인 필요로 표시한다.

### 보유세

- 2026년 주택 재산세 공정시장가액비율과 누진세율을 적용한다.
- 재산세, 지방교육세, 도시지역분, 지역자원시설세를 분리한다. 도시지역분은 대상 여부가 `해당`일 때만 0.14%를 적용하며, 지역자원시설세는 고지서의 전체 주택 금액을 입력받아 부부 지분만큼 포함한다.
- 주택 공시가격 합계에서 9억원 또는 1세대 1주택 12억원을 공제하고 60%를 적용해 종합부동산세를 계산한다.
- 종부세는 본인·배우자를 고정된 납세의무자로 분리하고 각 납세의무자가 소유한 주택 수로 2주택 이하/3주택 이상 세율을 선택한다.
- 종부세에서 공제할 재산세액은 `실제 재산세 × 종부세 과세표준 해당 재산세 상당액 ÷ 합산 공시가격 재산세 상당액`의 시행령 공식을 적용하고 농어촌특별세 20%를 부가세에 포함한다.
- 세부담상한, 감면, 지자체 조례, 고령·장기보유 세액공제는 입력이 없어 Missing Input으로 표시한다.
- 분양권은 완공 전 재산세·종부세 과세 주택에서 제외한다.
- 공동명의 주택은 0% 지분도 역할을 유지해 본인과 배우자의 재산을 섞지 않고 지분별 재산세·종부세를 계산한다.
- 부부 공동명의 1주택이면 각자 9억원 공제의 개별 과세와 12억원 공제의 공동명의 특례 비교값을 모두 제공한다. 실제 합계에는 사용자가 `특례 신청/신청 예정`을 선택한 경우에만 특례를 적용한다.
- 공동명의 특례는 지분율이 높은 사람을 납세의무자로 사용하고 동일 지분이면 사용자가 본인/배우자를 선택한다. 6월 1일 기준 정확한 생년월일 만 나이와 취득일 기준 보유기간으로 고령자 20~40%, 장기보유 20~50%, 합계 최대 80%를 계산한다.

### 양도소득세

- 지분 반영 양도가에서 취득가와 필요경비를 차감한다. 보유·거주기간과 1년·2년 경계는 월 첫날로 반올림하지 않고 실제 날짜로 판정한다.
- 일반 부동산 장기보유특별공제는 3년 이상 연 2%, 최대 30%를 적용한다.
- 양도소득 기본공제는 납세의무자별·과세연도별 250만원 한도다. 같은 연도에 이미 사용한 금액을 입력해 잔액만 공제하고 거래 영향 시나리오의 연속 매도는 사용액을 자동 누적한다.
- 2년 미만 보유 주택은 기본세율과 단기세율을 비교해 큰 세액을 적용한다.
- 2021년 1월 1일 이후 취득 분양권·조합원입주권을 양도일의 세대 주택 수에 포함하며 주택별 `자동/포함/제외` 처리로 법정 제외주택을 명시한다.
- 종전주택 취득 1년 후 분양권을 취득하고 분양권 취득일부터 3년 이내 종전주택을 양도하면 `1주택+1분양권 특례`를 판정한다. 완공 후 경로는 분양권의 완공일, 완공 후 3년 내 이사일, 이사일부터 1년 계속 거주 확인일, 종전주택 양도기한을 날짜로 모두 검증한다. 기존 단일 체크값은 계산 근거로 사용하지 않는다.
- 1세대 1주택의 정확한 2년 보유와 필요한 경우 2년 거주를 확인한다. 2017년 8월 3일 전 취득은 조정대상지역이라는 이유만으로 거주요건을 추가하지 않고, 계약일 등 법정 면제 사유는 사용자가 확인해 입력한다.
- 특례가 아닌 조정대상지역 2주택은 기본세율에 20%p, 3주택 이상은 30%p를 더하고 장기보유특별공제를 배제한다. 중과 제외주택은 주택별 처리값으로 구분한다.
- 2026년 중과 유예는 2년 보유, 2026년 5월 9일 기준, 매매계약일, 계약금 수령, 토지거래허가 대상·신청일·승인, 지역별 4개월/6개월 및 9월 9일/11월 9일 최종기한을 검증한다. 기존 단일 체크값은 계산 근거로 사용하지 않는다.
- 공동명의 양도는 본인·배우자 지분별 과세표준과 기본공제·누진세액을 계산한 후 세대 합계로 표시한다.
- 완공된 재개발·재건축 자산은 현재 유형을 `아파트/주택`으로 유지하면서 `재개발·재건축 전 기존 주택을 매수한 자산`을 선택한다. 기존 주택 취득일·계약일·취득가, 관리처분계획 인가일, 철거·멸실일, 신축 사용승인·준공일, 추가분담금, 청산금 환급, 실제 취득세와 증빙 필요경비를 분리 저장한다.
- 재개발 양도 취득원가 후보는 `기존 주택 취득가 + 추가분담금 - 청산금 환급`으로 추적하고, 실제 취득세·재개발 증빙 경비는 필요경비로 별도 차감한다. 관리처분·멸실·준공 전후 보유·거주기간의 법적 효과는 Missing Input과 GPT 공식 법령 검증에 남기며 단순 합산값을 신고 확정액으로 표시하지 않는다.

## 시뮬레이션과 Revision

- 새 계산은 별도 Simulation으로 저장한다.
- 최신 세법 재계산은 Simulation의 최신 표시값을 갱신하되 이전 결과를 `SimulationRevision`에 계속 보존한다.
- 계산 근거를 펼치면 양도가·취득가·필요경비·양도차익·공제·과세표준·국세·지방세 Trace를 확인한다.
- 기존 거래 영향 시나리오 데이터와 계산기는 DB 호환을 위해 유지하지만 기본 화면에서는 AI의 복수 매도 순서 비교로 대체한다.
- 각 단계의 취득세 또는 양도세와 단계 적용 후 보유세를 계산하며, 최종 카드에는 거래세 합계와 연간 보유세 증감을 함께 표시한다.
- 여러 시나리오 카드를 같은 화면에 두어 결과를 비교할 수 있다. 가상 취득 자산을 후속 매도 단계의 대상으로 직접 고르는 UI는 후속 고도화 범위다.

## GPT 정밀분석

### 자연어 매도계획 분석

- 사용자는 전문 세무 항목 대신 날짜, 자산, 명의, 규제지역, 재개발·분양권, 거주와 매도계획을 아는 만큼 자유롭게 입력한다.
- `PROPERTY_TAX_SCENARIO_COMPARISON` 작업과 `gpt-5.6-sol`, reasoning effort `max`를 사용한다.
- 매 실행마다 공식 도메인 웹 검색을 강제하고 소득세법 시행령 제154조·제155조·제156조의2·제156조의3·제162조 및 관련 부칙을 우선 확인한다.
- 결과는 사실·계획·법정기한·불확실 항목이 구분된 타임라인, 추천 시나리오, 매도 순서, 자산별 세금 처리 가능성, 장점·위험·기한으로 구조화한다.
- 부부 명의가 달라도 세대 기준 판정을 검토하며, 분양권 취득일과 준공 후 실제 주택 취득일, 재개발 관리처분·멸실·준공일을 구분한다.
- 금액이 없으면 세액을 생성하지 않는다. 미래 거래는 현재 법령 기준의 조건부 전망으로 표시하며 비과세를 확정하지 않는다.
- 추가 질문은 결론을 바꿀 수 있는 정보만 최대 6개로 제한한다. 재분석 시 직전 결과는 비교 문맥일 뿐 정답으로 사용하지 않는다.
- 기존 포트폴리오·Rule Engine은 상세 세액 산출과 교차검증을 위한 선택 기능으로 유지한다.

### 저장된 상세 계산 분석

- 공통 `AIModelRouter → OpenAiProvider → Firebase Callable Function` 경로만 사용한다.
- Task는 `PROPERTY_TAX_DEEP_ANALYSIS`, 모델은 `gpt-5.6-sol`, reasoning effort는 `max`로 서버에서 강제한다.
- 사용자가 `최신 법령 + GPT`를 누를 때마다 호출하며 캐시를 재사용하지 않는다.
- 같은 시뮬레이션의 직전 분석은 비교 문맥으로만 첨부한다. 직전 결과가 있어도 공식 검색과 새 모델 응답은 매번 다시 실행한다.
- Callable Function은 OpenAI Responses API의 `web_search`를 `tool_choice=required`로 강제한다.
- 검색은 국가법령정보센터·국세청·기획재정부·행정안전부·위택스·국토교통부 공식 도메인으로 제한한다.
- 서버가 공식 검색 출처를 별도로 추출하며 출처가 하나도 없으면 분석을 실패 처리한다.
- 현행 조문뿐 아니라 시행일·부칙·경과규정·일몰 및 유예 종료일을 확인해 현재 Rule Engine과 비교한다.
- 결과는 `CURRENT`, `CHANGE_DETECTED`, `INCONCLUSIVE`로 구분한다. 변경 감지 또는 검증 불완전이면 `calculationSafe=false`로 표시해 현재 계산값의 확정 사용을 막는다.
- 감지한 변경은 Rule ID, 시행일, 경과규정, 계산 영향으로 구조화하며 검색에 사용한 공식 출처를 화면에서 클릭 가능한 링크로 제공한다.
- 재분석 결과는 `이전 분석에서 바로잡은 내용`, `이번에 새로 확인된 차이`, `그대로 유효한 판단`으로 구분한다. 문구만 달라진 내용은 새 차이로 취급하지 않도록 프롬프트에서 제한한다.
- 첫 분석은 비교 영역을 표시하지 않는다. 두 번째 분석부터 직전 확인 시각과 비교 결과를 보여준다.
- 프롬프트는 공식 최신 법령과 일치하는 경우에만 Tax Engine 결과를 설명의 source of truth로 사용한다. AI의 숫자 재계산·수정 및 Rule 자동 활성화는 금지한다.
- 결과의 설명 구조는 summary, majorChanges, reasons, risks, missingInformation, suggestedScenarios를 유지한다.

### 법령 변경 처리 원칙

실시간 검색 결과가 현재 Engine과 다르더라도 AI 응답으로 세율·공제·계산식을 즉시 덮어쓰지 않는다. 신고에 직접 쓰이는 숫자는 검토 가능한 Kotlin Rule과 단위 테스트로만 변경한다. 변경 감지 시 계산 결과를 잠그고 공식 자료 검토 → Rule Version DRAFT → Golden Test → ACTIVE 배포 절차를 거친다.

## 안전 범위

표시되는 금액은 의사결정용 예상치이며 세무 신고나 세무·법률 자문을 대체하지 않는다. 특례 또는 Missing Input이 있는 결과는 `확인 필요`로 표시한다. 실제 거래 전에는 최신 법령과 증빙을 세무 전문가에게 확인해야 한다.
