# 부동산 경매 목록 기능명세서

## 1. 문서 정보

- 기능명: **부동산 경매**
- 목적: 매일 갱신되는 서울 소재 고가 아파트 경매 사건을 소림파워 앱에서 빠르게 확인한다.
- 상태: MVP 구현 완료
- 대상 앱: 개인용 Android 앱 SorimPower
- 데이터 원본: 대한민국 법원 법원경매정보 검색 API
- API URL: `https://www.courtauction.go.kr/pgj/pgjsearch/searchControllerMain.on`

## 2. 배경과 문제

사용자는 매일 새로 등록되거나 내용이 갱신된 부동산 경매 사건을 경매 사이트에서 반복해서 검색하는 불편을 줄이고 싶다. 앱은 법원경매정보 검색 API를 한국 시간 오전 9시 이후 하루 한 번 직접 조회하고 Room에 저장하여 다음 조건에 맞는 사건만 간결한 목록으로 제공한다.

고정 조회 조건은 다음과 같다.

- 소재지: 서울특별시
- 감정평가액: 10억 원 이상
- 진행 상태: 진행 중
- 용도: 아파트

이 기능의 핵심은 경매 사이트의 모든 기능을 대체하는 것이 아니라, 관심 범위의 사건을 매일 짧은 시간 안에 훑어보게 하는 것이다.

## 3. 목표

- 앱 진입만으로 고정 조건에 맞는 최신 경매 사건을 확인할 수 있다.
- Google Apps Script와 스프레드시트 없이 법원경매정보 원본을 앱의 로컬 캐시에 직접 반영한다.
- 매각기일, 가격, 주소, 사건번호 등 판단에 필요한 핵심 정보만 우선 표시한다.
- 마지막 데이터 갱신 시각을 명확히 표시하여 데이터의 신선도를 판단할 수 있다.
- 이전 조회와 비교해 새로 등장한 사건을 `신규`로 구분한다.
- 네트워크 장애가 있어도 마지막으로 성공한 목록을 확인할 수 있다.
- API 또는 원본 데이터에 조건 밖 사건이 섞여도 앱에서 한 번 더 제외한다.

- 내려받은 목록의 건물명을 대상으로 하는 아파트명 실시간 부분 검색

## 5. 사용자 시나리오

### 5.1 기본 조회

1. 사용자가 홈에서 **부동산 경매**를 선택한다.
2. 앱은 로컬에 저장된 최근 목록을 즉시 보여준다.
3. 오전 9시 이후 당일 동기화가 없으면 API 전체 페이지를 요청한다.
4. 모든 페이지가 성공하면 목록과 마지막 갱신 시각을 한 번에 갱신한다.
5. 사용자는 매각기일이 가까운 사건부터 핵심 정보를 확인한다.
6. 화면 목록은 완성된 로컬 스냅샷에서 바로 탐색한다.

### 5.2 신규 사건 확인

1. 앱이 한 번 이상 성공적으로 동기화되어 기준 목록을 보유한다.
2. 다음 동기화에서 이전에 없던 `itemKey`가 발견된다.
3. 해당 카드에 `신규` 배지를 표시한다.
4. 최초 설치 후 첫 동기화에서는 모든 항목을 신규로 표시하지 않는다.

### 5.3 새로고침 실패

1. 사용자가 화면을 열거나 직접 새로고침한다.
2. 네트워크 또는 API 오류가 발생한다.
3. 저장된 목록이 있으면 그대로 유지하고 상단에 `최신 정보를 불러오지 못했어요`를 표시한다.
4. 저장된 목록이 없으면 오류 안내와 `다시 시도` 버튼을 표시한다.

## 6. 화면 명세

### 6.1 홈 기능 카드

- 제목: `부동산 경매`
- 설명: `서울·감정가 10억 이상 진행 중 아파트`
- 배지: `DAILY`
- 선택 시 경매 목록 화면으로 이동
- 홈의 기능 개수 문구를 실제 카드 수와 일치시킨다.

### 6.2 목록 화면 상단

- 화면 제목: `부동산 경매`
- 공통 보라·핑크 요약 카드: 진행 중 전체 건수와 고정 관심 조건 표시
- 고정 조건은 상단 요약 카드의 `서울 · 아파트 · 감정가 10억 이상` 문구로 간결하게 표시하며 검색·정렬 카드에서 중복 표시하지 않는다.
- 결과 수: `총 N건`
- 데이터 시각: `데이터 갱신 8월 6일 08:42`
- `lastUpdatedAt`에는 앱이 법원 API 전체 페이지 수집을 성공한 시각을 저장한다.
- `lastUpdatedAt`이 없으면 `갱신 시각 확인 불가`로 표시한다.

### 6.3 사건 카드

카드에는 API의 모든 필드를 노출하지 않고 아래 정보만 표시한다.

#### 항상 표시

- `신규` 배지: 이전 성공 동기화에 없던 사건만 표시
- 매각기일 및 정규화한 시간: 예) `8월 21일(금) 10:00`. 우상단 북마크와 겹치지 않도록 최대 2줄로 전체 표시
- 남은 기간: 예) `D-15`, 당일이면 `오늘`, 지난 날짜이면 `기일 경과`
- 건물명: 값이 없으면 `아파트 경매`
- 주소: 서울 구·동과 나머지 주소
- 사건번호와 물건번호
- 감정가
- 최저가
- 최저가 비율
- 유찰 횟수
- 담당 법원
- 사건번호: 탭하면 `타경` 뒤의 숫자만 클립보드에 복사하고 완료 안내 표시
- 캘린더 등록: 매각일·시간을 일정 시각으로, 사건번호·물건번호·아파트명·가격·법원·주소·비고·법원 링크를 일정 설명으로 전달

#### 조건부 표시

- 비고: 값이 있을 때 기본 2줄, 넘치는 경우 비고 박스 전체를 탭해 원문 전체 보기·접기
- 구성물건수: 2개 이상일 때만 `구성물건 N개`
- 경매 장소: 공간이 허용되고 값이 있을 때만 보조 정보로 표시

#### 기본적으로 표시하지 않음

- 법원코드
- 내부사건번호
- 담당계 전화번호
- 관심물건등록수
- 수집일시
- 시도·시군구·동의 개별 원본 필드

전화번호 등 숨긴 필드는 향후 상세 화면이 필요할 때 사용할 수 있도록 데이터 모델에는 유지할 수 있다.

### 6.4 가격 표시

- 원 단위 원본값은 `Long`으로 처리한다.
- 1억 원 이상은 억 단위로 읽기 쉽게 표시한다.
- 예: `1,250,000,000` → `12억 5,000만 원`
- 카드 가격 영역 예시:
  - `감정가 12억 5,000만 원`
  - `최저가 10억 원 · 80%`
- 값이 0이거나 파싱할 수 없으면 `가격 정보 없음`으로 표시하고, 감정가 조건 검증에는 실패한 것으로 처리한다.

### 6.5 목록 상태

#### 최초 로딩

- 카드 형태의 스켈레톤 또는 중앙 로딩 표시
- 기존 캐시가 있으면 로딩 표시 대신 캐시를 즉시 노출

#### 빈 목록

- 문구: `현재 조건에 맞는 진행 중 경매가 없어요.`
- 마지막 갱신 시각은 계속 표시
- `다시 확인` 버튼 제공

#### 전체 요청 실패

- 문구: `경매 목록을 불러오지 못했어요.`
- 원인별 상세 기술 문구는 로그에 남기고 사용자에게는 간단히 표시
- `다시 시도` 버튼 제공

#### 일부 페이지 실패

- 기존 Room 목록 전체를 유지하고 새 응답은 반영하지 않는다.
- 상단에 최신 정보를 불러오지 못했다는 안내와 재시도 버튼을 표시한다.

#### 오래된 데이터

- 현재 시각 기준 `lastUpdatedAt`이 36시간보다 오래되면 `데이터가 오래되었어요` 배지 표시
- 오전 9시 이전에는 전날 데이터가 표시될 수 있음을 허용한다.

## 7. 법원경매정보 API 분석 및 계약

### 7.1 요청

앱은 다음 검색 엔드포인트에 JSON POST를 보낸다.

```text
POST https://www.courtauction.go.kr/pgj/pgjsearch/searchControllerMain.on
```

필수 헤더는 `Accept: application/json`, `Content-Type: application/json;charset=UTF-8`, 모바일 Chrome 계열 `User-Agent`, `SC-USERID: SYSTEM`, `submissionid: mf_wfm_mainFrame_sbm_selectGdsDtlSrch`, 검색 화면 `Referer`다. 기본 curl 식별자는 법원 WAF가 HTTP 200의 HTML 차단 페이지로 응답했지만 모바일 Android 식별자를 포함한 동일 요청은 JSON 응답을 반환하므로, 앱은 `User-Agent`를 명시하고 응답 본문 형식을 별도로 검증한다. 요청 본문에는 다음 조건을 지정한다.

- 페이지 크기: 40
- 소재지 시도 코드: `11`(서울특별시)
- 용도 코드: `20000` → `20100` → `20104`(건물 → 주거용건물 → 아파트)
- 감정평가액 최솟값: `1000000000`
- 상태: 진행 중
- 매각기일: 조회일로부터 90일 이내

페이지 사이에는 법원 서버 부하를 줄이기 위해 1초 간격을 두며, 첫 페이지의 `totalCnt`로 전체 페이지를 계산한다. 페이지 수와 응답 페이지 번호가 수집 도중 달라지면 전체 동기화를 실패 처리한다.

### 7.2 응답 검증

HTTP 2xx뿐 아니라 JSON 루트의 `status == 200`, `data.ipcheck != false`, `data.dlt_srchResult` 배열 존재를 모두 확인한다. HTML, JSON 구조 오류, IP 차단, 일부 페이지 실패가 발생하면 기존 Room 스냅샷을 보존한다.

법원 응답의 주요 영역은 다음과 같다.

```json
{
  "status": 200,
  "data": {
    "ipcheck": true,
    "dma_pageInfo": { "pageNo": 1, "totalCnt": 28 },
    "dlt_srchResult": []
  }
}
```

### 7.3 원본 필드 변환

| 법원 필드 | 앱 필드 | 처리 |
|---|---|---|
| `groupmaemulser` | `itemKey` | 없으면 `boCd-saNo-maemulSer` 조합 |
| `jiwonNm`, `boCd` | 법원명·법원코드 | 문자열 저장 |
| `srnSaNo`, `saNo`, `maemulSer` | 사건번호·내부사건번호·물건번호 | 문자열 저장 |
| `dspslUsgNm` | 용도 | `아파트`인지 재검증 |
| `gamevalAmt` | 감정평가액 | `Long`, 10억 원 이상 재검증 |
| `notifyMinmaePrice1`, `minmaePrice` | 최저가 | 고지 최저가 우선, 비율은 앱에서 재계산 |
| `yuchalCnt` | 유찰 횟수 | 정수 변환 |
| `maeGiil`, `maeHh1` | 매각일·시간 | `yyyyMMdd` → `yyyy-MM-dd`, `HHmm` → `HH:mm` |
| `printSt`, `hjguSido`, `hjguSigu`, `hjguDong` | 주소·행정구역 | 서울 여부 재검증 |
| `buldNm`, `jpDeptNm`, `tel`, `mulBigo` | 건물명·담당계·전화·비고 | 문자열 저장 |
| `gwansMulRegCnt`, `mulJinYn` | 관심 수·진행 여부 | 숫자 및 `Y` 여부 변환 |

같은 `groupmaemulser`를 가진 여러 구성행은 하나의 `AuctionItem`으로 묶고 그 행 수를 `objectCount`로 저장한다.

### 7.4 앱 측 조건 재검증

법원 검색 조건과 별개로 원본 행 및 변환된 항목에 다음 조건을 다시 적용한다.

```text
서울특별시 코드 또는 명칭 일치
appraisalPrice >= 1_000_000_000
isInProgress == true
usageName == "아파트"
itemKey가 비어 있지 않음
```

오피스텔, 다세대, 연립주택, 상가 등은 임의로 아파트에 포함하지 않는다.

### 7.5 종료 사건

법원 API는 앱 전용 종료 이력을 제공하지 않으므로 직전 성공 스냅샷과 새 스냅샷을 앱에서 비교한다. 직전에는 존재했지만 새 검색 결과에서 사라진 `itemKey`를 `REMOVED`로 별도 Room 테이블에 한 번만 누적한다. 이 상태는 낙찰·취하·기일 변경 중 어느 원인인지 확정하지 않는다.

## 8. 로컬 데이터 및 신규 판정

### 8.1 저장 목적

- 화면 진입 즉시 최근 목록 표시
- 네트워크 실패 시 마지막 목록 제공
- 전날 목록과 비교한 신규 사건 판정

### 8.2 로컬 모델 예시

```kotlin
AuctionItemEntity(
    itemKey: String,

    minimumPrice: Long,

```

가격은 `Int` 범위를 넘을 수 있으므로 반드시 `Long`을 사용한다.

### 8.3 신규 판정 규칙

- 첫 번째 성공 동기화: 기준 데이터로 저장하고 모든 항목의 `isNew=false`
- 이후 성공 동기화: 기존 DB에 없는 `itemKey`만 `isNew=true`
- 같은 `itemKey`의 가격·기일 등이 바뀌면 기존 항목을 갱신하되 신규로 보지 않는다.
- 신규 배지는 사용자가 화면에서 본 뒤 즉시 없애지 않고 해당 동기화 동안 유지한다.
- 화면에서는 `firstSeenAt`의 서울 날짜가 오늘인 사건에만 `신규` 배지를 표시한다.
- API 전체 페이지 동기화가 성공한 경우에만 사라진 항목을 로컬 목록에서 제거한다.
- 일부 페이지만 성공한 경우 기존 항목을 삭제하지 않는다.

## 9. 데이터 동기화 정책

- 화면 진입 시 캐시를 먼저 표시하고 API를 요청한다.
- 사용자가 당겨서 새로고침할 수 있다.
- 당겨서 새로고침과 재시도 버튼은 일일 캐시 정책을 무시하고 법원 API를 즉시 호출한다.
- 같은 화면 세션에서 불필요한 중복 요청을 막는다.
- 한국 시간 오전 9시 이후 첫 화면 진입에서만 자동 동기화하며 앱 자체의 정기 백그라운드 작업은 사용하지 않는다.
- 네트워크 연결·읽기 제한 시간을 두고 무한 대기하지 않는다.
- 첫 페이지 응답의 `totalCnt`로 전체 페이지를 계산하고 이후 페이지 응답의 일관성을 검증한다.
- 중복 `itemKey` 구성행은 하나로 합치고 행 개수를 `objectCount`로 저장한다.
- 모든 페이지의 성공을 확인한 뒤 하나의 동기화 트랜잭션으로 캐시를 교체한다.

목록을 무한 스크롤로 표시하더라도 신규 판정과 완전한 오프라인 캐시를 위해 저장소 계층은 전체 페이지 동기화를 수행할 수 있다. 데이터량이 커지면 Paging 도입을 검토한다.

## 10. 앱 구조

기존 프로젝트 규칙에 맞춰 다음 패키지를 사용한다.

```text
feature/auction/
├── data/
│   ├── CourtAuctionApi.kt
│   ├── AuctionDatabase.kt 또는 공통 Room 확장
│   └── AuctionRepository.kt
├── domain/
│   └── AuctionModels.kt
└── presentation/
    ├── AuctionScreen.kt
    └── AuctionViewModel.kt
```

- `data`: 법원경매정보 HTTP 요청, 원본 구성행 병합·JSON 변환, Room 캐시, 앱 조건 재검증과 종료 사건 감지
- `domain`: 가격·날짜 포맷과 신규 판정에 필요한 순수 로직
- `presentation`: 목록 상태와 Compose UI
- 홈 화면: 세 번째 기능 카드 추가
- 앱 셸: `AUCTION` 화면과 상단 제목 연결
- 설정의 시작 화면 선택에는 실제 사용 후 필요할 경우 추가

추가 네트워크 의존성 없이 `HttpURLConnection`과 Android `JSONObject`를 사용한다. Android Manifest에는 인터넷 권한이 필요하다.

## 11. 오류 및 데이터 방어 규칙

- HTTP 오류 또는 `status != 200`: 서버 오류로 처리하고 `message`는 진단에만 사용한다.
- 응답이 HTML: 법원 WAF 차단 응답으로 분류하고 캐시를 유지한다.
- JSON 구조 오류: 캐시를 보존하고 새 데이터로 덮어쓰지 않는다.
- `itemKey`가 비어 있음: 해당 항목 제외
- 감정가가 0·음수·파싱 불가: 해당 항목 제외
- 날짜 파싱 실패: 목록 하단에 배치하고 `기일 미정` 표시
- 매각시간 `HHmm`: `HH:mm`으로 정규화하고 실패하면 시간 숨김
- `isInProgress=false`: 제외
- 고정 조건 불일치: 제외하고 진단 로그에 개수만 기록
- 중복 사건: `itemKey` 기준 병합
- 계산한 전체 페이지 범위를 넘으면 추가 요청 중단
- 서버가 같은 페이지를 반복 반환: 무한 페이지 요청을 막고 실패 처리

## 12. 접근성 및 표시 원칙

- 가격 정보는 색상만으로 구분하지 않고 `감정가`, `최저가` 라벨을 함께 표시한다.
- `신규`, `유찰 N회`, `D-N` 배지는 스크린 리더가 읽을 수 있는 설명을 제공한다.
- 사건 카드의 터치 영역은 최소 48dp를 확보한다.
- 긴 주소·건물명은 최대 줄 수를 정하고 말줄임 처리하되 사건번호와 가격은 생략하지 않는다.
- 날짜와 가격은 한국어 로케일로 표시한다.

## 13. 보안·법적 유의 사항

- 앱에는 API 키, 법원 계정 또는 기타 인증 정보를 저장하지 않는다.
- API는 읽기 전용 공개 데이터만 반환한다.
- 법원 경매 정보는 변경·취소될 수 있으므로 화면 하단에 다음 안내를 표시한다.

> 이 목록은 간편 확인용입니다. 입찰 전 매각기일과 사건 상태를 법원 경매정보에서 다시 확인하세요.

- API 원본 사이트의 이용 조건과 자동 수집 허용 범위는 운영자가 별도로 준수한다.
- 앱은 투자 판단, 권리분석 또는 입찰 결과를 보장하지 않는다.

- 직전 Room 스냅샷에는 있었지만 새 법원 검색 결과에서 사라진 사건을 종료 사건으로 감지해 별도 Room 테이블에 누적
- 진행 목록 교체와 종료 사건 추가를 하나의 Room 트랜잭션으로 처리해 일부 결과가 캐시에 반영되지 않도록 보장
- 각 종료 사건 카드 최하단의 `기록 삭제` 버튼과 확인창 제공. 삭제 대상과 연결된 관심 사건 키도 함께 삭제하고 마지막 이력 삭제 시 이력 메타데이터를 정리
- 종료 사건 카드에서 낙찰·취하 등 정확한 사유를 확인할 수 없음을 명시
- 사건번호 영역을 탭하면 `타경` 뒤 숫자만 클립보드에 복사하고 토스트로 완료 안내
- 사건 카드의 아파트 이름을 탭하면 법원경매정보 물건 조회 화면을 외부 브라우저로 열기
- 진행 중 사건 카드 하단의 `캘린더 등록`에서 시스템 일정 작성 화면 열기. 시간이 없으면 종일 일정, 시간이 있으면 서울 시간 기준 1시간 일정으로 입력
- 진행 중일 때 저장한 관심 사건 키를 별도 유지하여 종료 사건 카드에서도 동일한 관심 북마크 표시
- 하단 메뉴의 부동산 경매 탭과 `더보기` 탭 기반 확장 구조
- 캐시가 있을 때 새로고침 실패 안내와 기존 목록 유지
- 인터넷 권한과 도메인 단위 테스트 추가

후속 확인 사항은 법원경매정보 서비스의 자동 수집 정책과 실제 Android 네트워크에서의 IP 허용 여부를 운영 환경에서 지속 확인하는 것이다.
